# qc-vision-inspector

Binary visual defect detector (`good` / `bad`) for industrial quality control, built on the MVTec AD transistor subset.

## Results (5-fold CV, 273 good / 40 bad)

| Phase | Method | Mean F1 | Mean AUROC | Notes |
|-------|--------|---------|------------|-------|
| A | DINOv2-base linear probe (logReg, Optuna-tuned) | ~0.76 | ~0.98 | Production backbone; cut `0.046` = mean of FAR@5% fold cuts |
| B | PatchCore + WideResNet-50 | ~0.60 | ~0.89 | Beats ResNet-18 bank; FAR-calibrated cuts |
| C | EfficientAD (`em` size) | ~0.77 | ~0.97 | Best single model; fold 3 reaches F1 1.0 |
| D | Fusion: DINOv2 + EfficientAD (stacked LR) | ~0.81 | ~0.99 | Best overall operating point |
| E | Threshold sweep + per-defect autopsy | F1 0.87 | — | `global-max` cut: recall 0.925 @ FAR 0.029 |

DINOv3 variants were evaluated as gated backbones but DINOv2-base (public) won on stability and stayed the production pick.

## Dataset

`transistor_binary/` (tracked with Git LFS) is derived from [MVTec AD](https://www.mvtec.com/company/research/datasets/mvtec-ad) `transistor`:

- `good/` — 273 images, `bad/` — 40 images, plus `labels.csv` (`filename,label,defect,source,original_path`)
- Defect types: `bent_lead`, `cut_lead`, `damaged_case`, `misplaced`
- The original MVTec archive (~5 GB) is **not** versioned; re-derive with your own download (research-only license, see below)

## Setup

Requires Python 3.12 and [uv](https://docs.astral.sh/uv/). Torch ships with CUDA 12.8 via the pinned `pytorch-cu128` index in `pyproject.toml` — do not remove it.

```bash
uv sync
cp .env.example .env   # add HF_TOKEN only if you need gated HF models (DINOv3)
uv run marimo edit --no-token --port 2718 fase_a.py
uv run mlflow ui       # sqlite:///mlflow.db, experiment "transistor-binary"
```

Verify GPU: `uv run python -c "import torch; print(torch.__version__, torch.cuda.is_available())"` → `+cu128 True`.

## Pipeline

Each `fase_*.py` is a [marimo](https://marimo.io/) notebook (run, don't import):

| Notebook | What it does | Key outputs |
|----------|--------------|-------------|
| `eda.py` | Exploratory analysis of the binary split | `mlfigs/` |
| `fase_a.py` | DINOv2/DINOv3 embeddings + Optuna + logistic probe | `fase_a_fold_metrics*.csv`, `fase_a_optuna*.csv`, `thresholds_dinov2.json` |
| `fase_b.py` | PatchCore memory banks (R18 / WRN-50) | `fase_b_fold_metrics_*.csv`, `thresholds_patchcore_*.json` |
| `fase_c.py` | EfficientAD via anomalib (`em` / `es`) | `fase_c_fold_metrics_*.csv`, `thresholds_efficientad_*.json` |
| `fase_d.py` | Score fusion: alpha-blend + stacked LR | `fase_d_fold_metrics.csv` |
| `fase_e.py` | Operating-point sweep + per-defect autopsy | `fase_e_sweep.csv`, `fase_e_autopsia.csv` |
| `fase_f.py` | Production export (final thresholds) | `thresholds.json` |

Metrics and thresholds are committed; bulky artifacts (`*.pt` banks/embeddings, `*.ckpt` checkpoints, `results*/`, `mlruns/`, `mlflow.db`) are git-ignored and regenerated by re-running the notebooks.

## Reproducibility

- `uv.lock` is committed; `uv sync` restores the exact env.
- `transistor_binary/` + `labels.csv` are in LFS so folds/splits rebuild identically.
- Notebook convention: one marimo cell per step; re-running cascades downstream (see `AGENTS.md`).
